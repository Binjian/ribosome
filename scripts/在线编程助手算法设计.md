# 算法设计文档：基于 Tree\-sitter 的智能机器人编程助手

## 文档概述

本设计文档旨在描述如何将自定义的机器人语言语法（Siasun）集成到在线编程助手中。该系统的核心目标是根据用户的自然语言输入（例如“移动到P1并等待”），生成语法正确的机器人控制代码，并利用 Tree\-sitter 提供实时的语法验证和代码结构分析。

## 系统架构设计

系统由三个主要模块组成：

- **语法构建模块 \(Grammar Build Module\)**：基于 `grammar.js` 编译语言解析库。

- **代码生成与解析服务 \(Generation \& Parsing Service\)**：处理用户请求，生成代码草稿，并使用 Tree\-sitter 生成抽象语法树（AST）。

- **验证与反馈模块 \(Validation \& Feedback\)**：遍历 AST 以确保生成的代码符合特定的机器人编程规范（如 `NOP`/`END` 结构）。

- **动态仿真 \(Dynamic Simulation\)**：解释器逐行执行 AST，更新虚拟寄存器状态。

- **反馈迭代 \(Feedback Loop\)**：将错误信息（语法错误或逻辑异常）回传生成器进行修正。

## 详细模块设计

### 模块一：语法定义与集成 \(Grammar Integration\)

**目标**：定义机器人语言的词法和句法规则，使其能被 Tree\-sitter 识别。

• **输入**：

◦ 新松机器人 `grammar.js`。

◦ 库卡（KRL）`grammar.js`。

• **处理逻辑**：

◦ **新松 \(Siasun\)**：定义解释型脚本结构。必须包含 `program_header` \(NOP\) 和 `program_footer` \(END\)。支持变量（I, R, P, PR）和运动指令（MOVJ, MOVL）。

◦ **库卡 \(KRL\)**：定义大小写不敏感的解析规则（如 `DEF` vs `def`）。处理 `.src` 和 `.dat` 文件结构以及折叠（Folds）。

• **输出**：生成的 `.so` \(Linux\) 或 `.dll` \(Windows\) 动态链接库文件。

### 模块二：解析器构建流程 \(Parser Build Workflow\)

**算法描述**： 根据源文档 提供的 Python 构建脚本，系统初始化时需加载编译好的语言库。

1\. **环境准备**：安装 `tree-sitter` Python 绑定。

2\. **编译库文件**： 使用 Python 脚本调用 `Language.build_library`，将包含 `grammar.js` 的目录编译为 `siasun_robot.so` 或 `krl.so`。

3\. **加载语言**： 在主程序中实例化 `Language('siasun_robot.so', 'siasun_robot')`。

步骤 3：AST 结构验证 \(AST Validation\)

解析器不仅能高亮代码，还能检测语法错误。算法需遍历 AST 节点以验证完整性。

• **完整性检查**：

◦ 对于新松语言，检查 `root_node` 的第一个子节点是否为 `program_header` \(NOP\)，最后一个是否为 `program_footer` \(END\)。

◦ 检查是否存在类型为 `ERROR` 或 `MISSING` 的节点（Tree\-sitter 的标准错误处理机制）。

• **特定规则校验**：

◦ **运动指令检查**：验证 `motion_statement` 是否包含合法的参数（如 `VJ=`, `ACC=`）。

◦ **变量检查**：确保赋值语句 `assignment` 中的变量类型匹配（如 `SET I1` 对应整数）。

步骤 4：生成反馈

• **成功**：如果 AST 无错误节点，返回代码及用于前端高亮的语法树结构（如将 `MOVJ` 标记为关键字，`P1` 标记为变量）。

• **失败**：如果发现 `ERROR` 节点，定位错误行号，提示用户或触发自动修复机制。

### 模块四：新松虚拟解释器 \(Siasun Virtual Interpreter\) / 物理新松解释服务器

由于新松语言被定义为“解释型（脚本）语言”，其执行逻辑类似于 BASIC，支持逐行解析。我们将构建一个轻量级的 Python 类来模拟机器人控制器（RC）的行为。

**核心组件**：

• **虚拟内存 \(Register Bank\)**：模拟全局变量存储区。根据源文档，新松主要依赖编号寄存器。

◦ `I`: 整数寄存器 \(Dictionary: `{'I1': 0, ...}`\)

◦ `R`: 实数寄存器

◦ `P`: 位置变量 \(Mock Object\)

◦ `OUT`: IO 端口状态

• **程序计数器 \(PC\)**：指向当前执行的 AST 节点。

• **AST 执行器**：遍历由 Tree\-sitter 生成的语法树，并执行对应逻辑。

**支持的指令逻辑 \(基于 Source Grammar\)**：

• **运算指令** \(`assignment`, `math_operation`\)：直接更新 Python 字典中的值。例如 `SET I1 0` 将更新虚拟内存 `I = 0`。

• **流控制** \(`if_statement`, `goto_statement`\)：

◦ `IF I1 < 5 L10`：计算条件表达式。如果为真，查找标签 `L10` 对应的 AST 节点索引并更新 PC。

◦ 防止死循环：设置最大执行步数（如 1000 步）。

• **运动与IO** \(`motion_statement`, `io_statement`\)：

◦ 由于没有物理硬件，解释器将“记录”这些操作。

◦ 例如 `MOVJ P1` \-\> 记录日志 `[Motion] Moved to P1 with params...`。

◦ 例如 `OUT OT#1=ON` \-\> 更新状态 `IO['OT#1'] = True`。

### 模块五：自动迭代与测试循环 \(Iteration \& Testing Algorithm\)

**算法流程**：

1\. **初始化**：用户输入意图，定义最大重试次数 `MAX_RETRIES = 3`。

2\. **生成阶段**：生成代码 `code_candidate`。

3\. **静态检查 \(Tree\-sitter\)**：

◦ 调用 `grammar.js` 编译的库进行解析。

◦ 如果发现 `ERROR` 节点，生成错误报告（例如：“第 3 行语法错误，缺少参数”），**跳至步骤 6**。

4\. **动态执行 \(Interpreter\)**：

◦ 初始化 `VirtualInterpreter`。

◦ 运行代码。

◦ **捕获异常**：

▪ *除零错误*。

▪ *死循环*（超时）。

▪ *未定义标签跳转*。

▪ *逻辑断言失败*（例如：用户要求 I1=5，但执行后 I1=0）。

◦ 如果发生异常，生成运行时错误报告，**跳至步骤 6**。

5\. **成功/输出**：

◦ 如果无错误，收集执行日志（“测试用例”）。

◦ 输出代码 \+ 变量最终状态表 \+ 模拟日志。

◦ **结束**。

6\. **迭代修复**：

◦ 如果 `retry_count < MAX_RETRIES`：

▪ 构建提示词：`"User Goal: {intent}. Current Code: {code}. Error: {error_msg}. Please fix the code."`

▪ 调用生成模型获取新代码。

▪ `retry_count += 1`，**返回步骤 3**。

◦ 否则，输出最后一次生成的代码并附带错误警告。

## 集成示例 \(Python 实现\)

### 生成的解析器集成到助手的后端服务：

以下代码展示了如何将生成的解析器集成到助手的后端服务中，用于验证用户生成的程序片段：

```Plain Text
from tree_sitter import Language, Parser

def validate_robot_code(code_string, language_type='siasun'):
    # 1. 选择语言库 (构建过程见源文档 [6])
    lib_file = 'siasun_robot.so' if language_type == 'siasun' else 'krl.so'
    lang_name = 'siasun_robot' if language_type == 'siasun' else 'krl'
    
    LANG = Language(lib_file, lang_name)
    parser = Parser()
    parser.set_language(LANG)
    
    # 2. 解析代码
    tree = parser.parse(bytes(code_string, "utf8"))
    root = tree.root_node
    
    # 3. 验证逻辑
    has_error = False
    
    # 递归检查错误节点
    def check_errors(node):
        nonlocal has_error
        if node.type == 'ERROR' or node.type == 'MISSING':
            has_error = True
            return
        for child in node.children:
            check_errors(child)
            
    check_errors(root)
    
    # 4. 针对新松语言的特殊结构检查 [1][9]
    if language_type == 'siasun':
        # 获取所有非空行语句
        statements = [c for c in root.children if c.type != 'comment' and c.type != 'empty_line']
        if not statements or statements.type != 'program_header': # 期望 NOP
            return {"valid": False, "msg": "Missing NOP at start"}
        if statements[-1].type != 'program_footer': # 期望 END
            return {"valid": False, "msg": "Missing END at finish"}

    return {"valid": not has_error, "ast_root": root.type}
```

### 结合 Tree\-sitter 的解析能力来实现一个简单的解释器

以下代码展示了如何结合 Tree\-sitter 的解析能力来实现一个简单的解释器，并将其集成到自动纠错流程中。

```Plain Text
from tree_sitter import Language, Parser
import time

# 1. 虚拟解释器类
class SiasunInterpreter:
    def __init__(self, parser_lib_path, lang_name):
        self.registers = {'I': {}, 'R': {}, 'OT': {}} # 虚拟寄存器
        self.logs = []
        self.labels = {} # 存储 Label 对应的节点位置
        
        # 初始化 Tree-sitter [5][3]
        self.LANG = Language(parser_lib_path, lang_name)
        self.parser = Parser()
        self.parser.set_language(self.LANG)

    def execute(self, code_str, max_steps=1000):
        self.registers = {'I': {}, 'R': {}, 'OT': {}} 
        self.logs = []
        tree = self.parser.parse(bytes(code_str, "utf8"))
        root = tree.root_node
        
        # 1. 预扫描：建立标签索引 (L10 -> AST Node Index) [2]
        children = root.children
        for idx, node in enumerate(children):
            if node.type == 'label_definition':
                # label_definition -> label_name -> text
                lbl_name = node.child_by_field_name('label_name').text.decode('utf-8')
                self.labels[lbl_name] = idx
        
        # 2. 逐行执行
        pc = 0 # Program Counter
        steps = 0
        while pc < len(children) and steps < max_steps:
            node = children[pc]
            steps += 1
            
            try:
                # 处理赋值: SET I1 0 [2]
                if node.type == 'logic_statement' and node.children.type == 'assignment':
                    assign_node = node.children
                    dest = assign_node.child_by_field_name('destination').text.decode('utf-8')
                    val_node = assign_node.child_by_field_name('source')
                    
                    # 简化处理：假设 source 是数字 (实际需处理变量递归)
                    val = float(val_node.text.decode('utf-8'))
                    
                    if dest.startswith('I'):
                        self.registers['I'][dest] = int(val)
                    elif dest.startswith('R'):
                        self.registers['R'][dest] = val
                    self.logs.append(f"EXEC: {dest} <- {val}")

                # 处理控制流: IF I1 < 5 L10 [2]
                elif node.type == 'control_statement' and node.children.type == 'if_statement':
                    if_node = node.children
                    # 这里需要实现 condition_expression 的求值逻辑
                    # 为简化示例，假设解析并判断为 True，执行跳转
                    target_node = if_node.child_by_field_name('target') # GOTO target
                    if target_node: # 简单的单行 IF 跳转
                         target_label = target_node.children[1].text.decode('utf-8')
                         if target_label in self.labels:
                             pc = self.labels[target_label]
                             self.logs.append(f"JUMP: To {target_label}")
                             continue # 跳过 pc += 1

                # 处理 IO: OUT OT#1=ON [4]
                elif node.type == 'io_statement':
                    self.logs.append(f"IO: Executed {node.text.decode('utf-8')}")

                # 检查 ERROR 节点 (Tree-sitter 静态报错)
                if node.type == 'ERROR':
                    raise ValueError(f"Syntax Error at line {node.start_point}")

            except Exception as e:
                raise RuntimeError(f"Runtime Error at line {node.start_point}: {str(e)}")
            
            pc += 1
            
        if steps >= max_steps:
            raise RuntimeError("Execution Timed Out (Possible Infinite Loop)")
            
        return {"success": True, "registers": self.registers, "logs": self.logs}

# 2. 自动迭代循环 (Mock)
```

## 总结

通过引入解释器模块，我们将设计从单纯的“语法检查”提升到了“语义验证”。

• **Tree\-sitter** 负责确保代码**写得对**（符合 中的语法规则，如 `NOP/END` 结构）。

• **解释器** 负责确保代码**跑得通**（符合 中的解释型执行逻辑，如变量状态流转）。

比喻

如果说之前的 Tree\-sitter 设计是 **“语法老师”（只管句子通顺，不管内容真假），那么现在加入的解释器就是“物理实验室”**。 学生（LLM）写出“把水烧到 200 度”这句话，语法老师会说“句子结构正确”，但物理实验室的模拟会立即报错“水在标准气压下 100 度就沸腾了，逻辑无法执行”。这个设计让我们的编程助手能够同时通过这两重考验，确保交给用户的代码既合乎语法，又合乎逻辑。

## 设计流程图如下

1\. **语法库构建 \(Build Phase\)**：

◦ 根据文档，Python 脚本需要调用 `Language.build_library` 将 `grammar.js` 编译为 `.so` 文件。这是解析器工作的先决条件。

2\. **静态语法检查 \(Static Syntax Check\)**：

◦ Tree\-sitter 解析代码字节流生成 AST。

◦ 算法在此处检查是否存在 `ERROR` 或 `MISSING` 节点，并验证特定规则，例如新松语言必须包含 `program_header` \(NOP\) 和 `program_footer` \(END\)。

3\. **虚拟解释器 \(Virtual Interpreter\)**：

◦ 这是我们在对话历史中新增的模块。

◦ 它模拟机器人控制器（RC）的行为，初始化虚拟寄存器（`I`, `R` 变量），并处理逻辑判断（`IF`, `GOTO`）。

4\. **自动修复循环 \(Feedback Loop\)**：

◦ 如果 Tree\-sitter 发现语法错误（如 `MOVJ` 缺少参数 `VJ=`）或解释器发现逻辑错误，系统不会直接报错，而是将错误信息反馈给 LLM 进行重新生成。
