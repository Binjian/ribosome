# AST Recursion Refactoring in `reorg_node`

## 1. Executive Summary

This document details the architectural review, identified vulnerabilities, and refactoring plan for `reorg_node` and its companion recursive helper `reorg_section` in `ribosome.core.dom.reorg`.

The function `reorg_node` transforms a flat Pandoc Abstract Syntax Tree (AST) produced from Markdown into a hierarchical, section-nested DOM tree where `Header` nodes become root and child `Section` containers containing `Content` and `subnodes`.

While the initial implementation worked for single-pass conversion of flat, top-level `blocks`, deep analysis revealed critical flaws regarding **idempotency**, **structural boundary scoping (block vs. inline)**, **asymmetric list handling**, and **iterator efficiency**.

---

## 2. Comprehensive Problem Analysis

### 2.1. Lack of Idempotency: Destruction of Pre-Existing `Section` Trees
A Pandoc AST generated by `reorg_node` groups headers into `Section` structures:
```json
{
  "t": "Section",
  "c": [
    {"t": "Header", "c": [1, ["intro", [], []], [{"t": "Str", "c": "Intro"}]]},
    {"t": "Content", "c": [{"t": "Para", "c": [{"t": "Str", "c": "text"}]}]}
  ],
  "subnodes": []
}
```
In the original `reorg_node` implementation:
- It iterated through every dictionary key without checking if the dictionary itself is already a `Section`.
- Key `"c"` in `Section` has a list value `[Header, Content]`.
- `reorg_node` treated `Section["c"]` as an unorganized sequence of blocks.
- It took the inner `Header`, wrapped it in a *new* nested `Section`, and through `reorg_section`, swallowed the existing `Content` node into the new inner section's content.
- Result: Re-running `reorg_node` on an AST or sub-tree produced corrupted hierarchies:
  `Section -> Section -> Header, Content -> Content`.
- **Verdict**: Non-idempotent; catastrophic failure on multi-pass runs or sub-trees containing pre-existing sections.

### 2.2. Asymmetry in List Handling: Bare Lists vs. Dict Properties
- When a list was encountered as a dictionary value (`if isinstance(value, list):`), `reorg_node` performed TOC filtering, Header-to-Section conversion, and `reorg_section` hierarchy packing.
- When `node` itself was passed as a `list` (`elif isinstance(node, list):`), it only executed `[reorg_node(child) for child in node]`. It performed **no header conversion or section packing**.
- Consequently:
  - Calling `reorg_node(blocks)` directly on a list of blocks failed to reorganize anything.
  - Nested block lists inside lists (e.g., list items in `BulletList` or `OrderedList` in Pandoc: `[ [Item1Blocks], [Item2Blocks] ]`) were completely skipped by the reorganization logic.

### 2.3. Over-Traversal of Inline Nodes and Attributes
- Section reorganization is an exclusively **block-level** structural operation.
- In Pandoc AST, `Header` nodes only exist in block sequences (`blocks`, `BlockQuote['c']`, etc.).
- The original code unconditionally recursed through every dictionary and list in the document, including every paragraph's inline text elements (`Para['c']` consisting of words, spaces, styling spans) and attribute tuples (`[id, classes, kvs]`).
- For every inline list, it allocated temporary lists, checked for headers, created iterators, and executed the `while True: try: next(it)` loop. This caused significant allocation overhead and confused AST level semantics.

### 2.4. Inefficient Iterator Rewind ($O(N^2)$ Copies) and Dead Code in `reorg_section`
- In `reorg_section`, when a sibling or ancestor section was encountered (`next_level <= level`), the function rewound the iterator using:
  ```python
  it = iter([item] + list(it))
  ```
- Materializing `list(it)` copied all remaining downstream blocks across the entire document on every section boundary. For a document with $N$ sections, this led to $O(N^2)$ element copying and iterator re-instantiation.
- Lines 174-175 contained an `else:` branch (`next_level >= level + 2`) that was mathematically unreachable because `next_level > level`, `next_level == level`, and `next_level < level` form a complete partition of integers.

### 2.5. Out-of-Order Section Level Tracking and Action Bypass
- Bottom-up (post-order) traversal caused inner container blocks (such as `BlockQuote` containing a heading) to record section levels in `section_level` before outer sibling headings.
- The `action` callable was applied at node entry, meaning newly synthesized `Section` and `Content` wrappers were never passed through `action`.

## 3. Proposed Architecture & Refactoring

### 3.1. Idempotency Guard on `Section` Nodes
When `reorg_node` encounters a node where `node.get('t') == 'Section'`:
1. It registers the section header level in `section_level` if needed.
2. It recurses into `node['c'][1]['c']` (the `Content` block list) to organize any nested blocks (e.g., inside blockquotes).
3. It recurses into `node['subnodes']` to process child sections.
4. It **strictly avoids** treating `node['c']` (`[Header, Content]`) as a flat block list.

### 3.2. Unified Block Sequence Reorganization (`_reorg_blocks`)
Extract the sequence transformation logic into an explicit block reorganizer:
```python
def _reorg_blocks(blocks: list, section_level: list, action: Optional[Callable] = None, is_blocks_key: bool = False) -> list:
```
- Drops TOC blocks if `is_blocks_key` is `True`.
- Recursively processes child block elements.
- Identifies `Header` nodes (or leading `OrderedList` heading blocks) and turns them into flat `Section` nodes while recording `section_level`.
- Packs flat sections into nested hierarchies via `reorg_section`.
- Ensures both `dict[key]` block lists and bare block lists use the same logic.

### 3.3. Block-Level Scoping
Only apply the block reorganization pipeline to block sequences (`key == 'blocks'`, `key == 'c'` in block containers like `BlockQuote`, `Div`, or list item blocks). Skip running block-packing iterators over inline lists (e.g. `Para['c']`, `Str`, `Emph`).

### 3.4. Iterator Optimization via `itertools.chain`
Replace `iter([item] + list(it))` with:
```python
import itertools
it = itertools.chain([item], it)
```
This achieves $O(1)$ iterator prepending without materializing the remaining list in memory.

## 4. Verification and Test Strategy

1. **Regression Prevention**:
   - All 77 existing tests in the test suite must pass without regression.
2. **Idempotency Verification**:
   - `reorg_node(reorg_node(ast))` must equal `reorg_node(ast)` without creating nested `Section -> Section` structures.
3. **Bare List Processing**:
   - Passing `reorg_node(blocks, section_level=[])` directly must correctly transform headers into sections.
4. **Nested Containers**:
   - Headers inside block container blocks (e.g., `BlockQuote`) must be converted without corrupting outer sections.
